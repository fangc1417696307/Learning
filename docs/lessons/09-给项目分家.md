## 一、现状

你的 `main.py` 现在大概 60 行，还能一眼看完。

但你的项目要长成什么样？粗粗一数：

| 模块 | 大概需要 |
|---|---|
| 学生画像 | 增、查、改、列 |
| 学习资源生成 | 调 LLM、存结果 |
| 多智能体编排 | 规划、检索、生成、审核 |
| 用户 / 会话 | 登录、历史记录 |
| 前端联调 | 一堆接口 |

**每个模块三五个接口，加起来至少 20 个。** 全塞 `main.py`，它会变成 800 行、谁都不敢动的文件。

> **这不是"整洁癖"，是成本问题。**
> 800 行的文件，**你要找一个接口要滚很久，改一处要小心不碰坏旁边**，两个人同时改必然冲突。

## 二、先说清楚"按什么拆"

**错误的分法**：按"代码类型"拆（所有函数放一处、所有类放一处）。这是初学者的直觉，但它让"改一个功能"要翻三个文件。

**正确的分法**（第 7 课说过一次）：

> **按"变化的理由"拆。**

| 什么时候会改它 | 该放哪 |
|---|---|
| 接口的路径、参数、返回格式变了 | **路由层**（`routers/`） |
| 请求/响应的数据结构变了 | **模型层**（`schemas.py`） |
| 表结构、SQL 变了 | **数据层**（`db.py`） |
| 启动配置、挂载 | **入口**（`main.py`） |

**一个功能改需求时，理想情况是只动一两个文件。**

---

## 三、目标结构

```
backend/
├── main.py            入口：创建 app、挂载路由
├── db.py              数据层：连接、建表
├── schemas.py         模型层：请求/响应的数据结构
└── routers/
    ├── __init__.py
    └── profile.py     路由层：学生画像相关接口
```

> `routers/` 这个文件夹叫**包（package）**。`__init__.py` 可以是空文件。
> 它在 Python 3 里严格来说不是必需的（有"命名空间包"），但**建上它，兼容性和可读性都更好**，别省。
> 顺带：`backend/` 本身也是个包，只是习惯上不放 `__init__.py`。

## 四、`APIRouter`：路由的"分册"

`APIRouter` 和 `FastAPI` **用法几乎一样**——都能挂 `@xxx.get` / `@xxx.post`。区别只有一点：

> **`FastAPI` 是"整本书"，`APIRouter` 是"一章"。** 章最后要装进书里。

### 4.1 `backend/schemas.py`

```python
from pydantic import BaseModel


class ProfileRequest(BaseModel):
    name: str
    major: str
    age: int = 0
    goal: str = "未填写"


class ProfileResponse(BaseModel):
    id: int
    name: str
    major: str
    age: int
    goal: str
```

**注意多了一个 `ProfileResponse`——这是新东西。**

原来你的接口 `return` 一个普通的 dict，**没有任何约束**：字段写错、少写一个、多写一个，都能跑。

`ProfileResponse` 让**返回的数据也受 Pydantic 校验**。好处有三个：

1. `/docs` 里的"响应示例"是**真的**，不是瞎猜的
2. 返回结构写错了，**服务端立刻报错**，而不是让前端莫名其妙
3. **自动过滤多余字段**——如果哪天你从数据库把整行捞出来（包括密码、手机号），`response_model` 只输出模型里声明过的字段

> 第 3 个是安全意义。你的系统以后可能存学生的隐私信息，**"返回什么"必须由模型说了算，不能由"查出来什么"说了算。**

### 4.2 `backend/routers/profile.py`

```python
from fastapi import APIRouter, HTTPException

import db
from schemas import ProfileRequest, ProfileResponse

router = APIRouter(prefix="/profile", tags=["学生画像"])


@router.post("", response_model=ProfileResponse)
def create_profile(req: ProfileRequest):
    with db.get_db() as conn:
        cur = conn.cursor()
        cur.execute(
            "insert into students(name, major, age, goal) values (?, ?, ?, ?)",
            (req.name, req.major, req.age, req.goal),
        )
        new_id = cur.lastrowid

    return {
        "id": new_id,
        "name": req.name,
        "major": req.major,
        "age": req.age,
        "goal": req.goal,
    }


@router.get("/{student_id}", response_model=ProfileResponse)
def get_profile(student_id: int):
    with db.get_db() as conn:
        cur = conn.cursor()
        cur.execute(
            "select id, name, major, age, goal from students where id = ?",
            (student_id,),
        )
        row = cur.fetchone()

    if row is None:
        raise HTTPException(status_code=404, detail="不存在这个学生")

    return ProfileResponse(
        id=row[0],
        name=row[1],
        major=row[2],
        age=row[3],
        goal=row[4],
    )
```

**三个新东西：**

| 写法 | 作用 |
|---|---|
| `APIRouter(prefix="/profile")` | 这一章里所有路径**自动加前缀** |
| `tags=["学生画像"]` | `/docs` 里给这组接口**分组**，一眼看得清 |
| `response_model=...` | 返回的数据**按这个模型校验和过滤** |

> **`prefix` 的价值**：以后加 `GET /profile` 列表、`PUT /profile/{id}` 改资料，全都不用重复写 `/profile`。**路径只有一个地方定义，改起来只改一处。**

### 4.3 一个坑：`""` 和 `"/"` 不一样

```python
@router.post("", ...)      # ✅ 最终路径是 /profile
@router.post("/", ...)     # ⚠️ 最终路径是 /profile/ ——末尾多个斜杠
```

**`/profile/` 和 `/profile` 在 HTTP 里是两个不同的地址。** FastAPI 会做重定向（307），但：

- 有些前端库对重定向后的 POST **处理不一样**
- 调用方少写一个斜杠就多一次往返

**规矩：路径拼起来要刚好对，不靠重定向擦屁股。** 用 `""`。

### 4.4 `backend/main.py` 瘦身成什么

```python
from fastapi import FastAPI

import db
from routers import profile

db.init_db()

app = FastAPI()

app.include_router(profile.router)


@app.get("/")
def read_root():
    return {"message": "这是我第一个 FastAPI 应用程序！"}


@app.get("/hello/{name}")
def say_hello(name: str):
    return {"message": f"你好，{name}"}
```

`main.py` 现在只干一件事：**把各部分装到一起**。

> 一个健康的 `main.py` 通常**很短**。如果它越来越长，说明有东西没分出去。

## 五、会撞上的坑：导入找不到模块

拆成包以后，第一反应通常是跑不起来。几个必然出现的：

### 5.1 `ModuleNotFoundError: No module named 'routers'`

**原因**：和 uvicorn 那个坑是同一个——**`import` 按"当前工作目录"和"Python 的模块搜索路径"找文件。**

**解法**：在 `backend/` 下启动，别在 `Learning/` 下。

```bash
cd backend
uvicorn main:app --reload --port 8001
```

> 这是**第三次**遇到 cwd 了（第 1 课 uvicorn、第 2 课 `git add`）。**它值得刻进脑子里。**

### 5.2 循环导入 `ImportError: cannot import name ... from partially initialized module`

**原因**：A 导入 B，B 又导入 A，两边都还没加载完。

**你现在的结构为什么不会出**：依赖是**单向**的——

```
main.py  →  routers/profile.py  →  db.py / schemas.py
```

`db.py` 和 `schemas.py` **不 import 上面的任何东西**。

> **架构好的标志之一：依赖是单向的。** 哪天你发现 `db.py` 要 `import schemas`，而 `schemas` 又要 `import db`，那就是设计出问题了，不是"Python 的 bug"。

## 六、动手

1. 建 `backend/schemas.py`，把 `ProfileRequest` 搬过来，**新增 `ProfileResponse`**
2. 建 `backend/routers/__init__.py`（空文件）和 `backend/routers/profile.py`

5. **从 `backend/` 启动**，检查 `/docs`

### 验证清单

- [ ] `/docs` 里接口还在，而且**分了组**（"学生画像"）
- [ ] `POST /profile` 仍然返回新 id，而且**带了全部字段**
- [ ] `GET /profile/{id}` 能查到，**不存在的 id 返回 404**
- [ ] **重启后数据还在**（每次都要验，这是肌肉记忆）
- [ ] 访问一次 `http://127.0.0.1:8001/docs`，看响应示例里有没有 `ProfileResponse` 的样子

> ⚠️ **注意看 `POST /profile` 的返回变了**：
> 原来是 `{"id": 13}`，现在多了 `name`、`major`、`age`、`goal`。
> **这是"接口契约"变了**——如果前端已经按老的格式写了代码，会受影响。
>
> 真实项目里，这种改动要**提前通知前端**。这就是为什么第 1 课说 `/docs` 是"冻结接口契约"的工具。
