# 第 3 课：让接口能"接收数据"

> **日期**：2026-10-13
> **前置**：第 2 课（Git 版本控制）
> **目标**：让 FastAPI 接口能接收参数和请求体——这是写项目里每一个接口的基础

---

## 一、为什么这是分界线

你现在的接口**谁访问都一样**，返回固定的字符串。但真实系统里，接口必须接收用户给的数据。

在你的项目里就是：**学生说了一句话 → 这句话怎么传到后端？**

这是从"能跑"到"有用"的分界线。学完这一课，你就具备了写项目里每一个接口的能力。

---

## 二、三种传数据的方式

由简到繁，**第三种是真实项目的主力**：

| 方式 | 长相 | 用在哪 |
|---|---|---|
| **路径参数** | `/hello/张三` | 数据直接嵌在路径里，比如 `/profile/123` 取某人的画像 |
| **查询参数** | `/hello?name=张三` | 跟在 `?` 后面，常用于筛选、分页 |
| **请求体** | `POST` + JSON | **项目里 90% 的接口都是这个** |

## 三、动手：改 `main.py`

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class ProfileRequest(BaseModel):
    name: str
    major: str
    goal: str = "未填写"

@app.get("/")
def read_root():
    return {"message": "我的第一个 FastAPI 应用程序!"}

@app.get("/hello/{name}")
def say_hello(name: str):
    return {"message": f"你好，{name}"}

@app.post("/profile")
def create_profile(req: ProfileRequest):
    return {
        "student": req.name,
        "profile": {
            "专业": req.major,
            "学习目标": req.goal,
        }
    }
```

## 四、逐段讲解

### 4.1 路径参数

```python
@app.get("/hello/{name}")
def say_hello(name: str):
```

URL 里的 `{name}` 是个**占位符**。访问 `/hello/张三` 时，FastAPI 会自动把 `张三` 取出来传给你的函数。

**关键点**：函数参数上写了 `: str`，FastAPI 就会保证传进来的**一定是字符串**。

> 这就是"类型注解"在 FastAPI 里的第一个威力——**它不是给人看的注释，是给框架用的说明书。**

### 4.2 请求体 + Pydantic（重点）

```python
class ProfileRequest(BaseModel):
    name: str
    major: str
    goal: str = "未填写"
```

这个类描述了"我期望收到的 JSON 长什么样"。`BaseModel` 来自 **Pydantic**（FastAPI 自带的，不用单独装）。

**为什么必须要有这个东西？**

因为**进来的数据不可信**。用户可能少传字段、传错类型、传个空值。你不可能在每个函数里写一堆 `if` 去检查。Pydantic 帮你做了这件事：

- 字段名对不上 → 自动报错
- 类型不对（比如 `name` 传了数字）→ 自动报错
- 有默认值的字段可以省略 → `goal` 就是

> **这是你项目里极重要的一环**：以后你要让大模型把学生的自然语言抽成结构化画像，用的**就是同一套东西**——先用 Pydantic 定义好画像的结构，再去要求模型按这个结构输出。
