## 一、先看重复

你的 `routers/profile.py` 现在每个接口都长这样开头：

```python
def create_profile(req: ProfileRequest):
    with db.get_db() as conn:        # ← 这一行
        cur = conn.cursor()          # ← 这一行
```

```python
def get_profile(student_id: int):
    with db.get_db() as conn:        # ← 又是
        cur = conn.cursor()          # ← 又是
```

**目前两个接口，重复 4 行。** 按你项目的规模，最后会有 **20 个以上的接口**——同样 4 行要写 20 遍。

重复的代价不是"手累"，是这三件事：

| 代价 | 具体表现 |
|---|---|
| **漏写** | 20 个接口里总有一个忘了 `with`，连接就泄漏了，而且**很难被发现** |
| **改不动** | 哪天要换连接池、加超时、加日志，得改 20 处，改漏一处就出 bug |
| **看不出来** | 每个函数前两行都是噪声，真正重要的逻辑被埋在下面 |

> **判断标准**：同一段代码出现第 2 次，就该想能不能收起来；到第 3 次，几乎一定要收。

## 二、`Depends` 是什么

**一句话**：

> **函数不再自己去拿依赖，而是声明"我需要什么"，由框架负责递进来。**

对比一下：

```python
# 现在：自己拿
def create_profile(req):
    conn = db.get_db()      # 我主动 new 一个
    ...

# 用了 Depends：只要，不拿
def create_profile(req, conn: Connection = Depends(get_conn)):
    ...                     # 传进来时就已经有了
```

**这就是"依赖注入"（Dependency Injection）这个名字的字面意思**：依赖不是你自己创建的，而是**被注入进来的**。

### 为什么这比"少写两行"重要得多

| 好处 | 意思 |
|---|---|
| **一处定义** | 改连接方式只改 `get_conn` 一个函数 |
| **不可能漏** | 你只要声明了依赖，框架一定给你；不给就报错，不会静默漏掉 |
| **数据流清楚** | 函数签名直接告诉你"这个接口需要数据库" |
| **测试可替换** | 测的时候可以把数据库换成测试库，接口代码一行不改 |

> 最后一条是工程上的重头戏。现在你不用，但**面试问到"你怎么测试接口"，答案就是这个机制**。

## 三、新概念：`yield`

要让 `Depends` 管连接的关闭，得先认识 `yield`。**它比你想的简单。**

### 3.1 普通函数：跑到 `return` 就结束，回来就没了

```python
def normal():
    print("a")
    return 1
    print("b")        # 永远不执行
```

调用一次 → 执行一次 → 函数状态全部销毁。

### 3.2 带 `yield` 的函数：可以**暂停**，之后还能**接着跑**

```python
def with_yield():
    print("第一步")
    yield 1               # ← 暂停在这里，把 1 交出去
    print("第二步")
    yield 2
    print("第三步")        # ← 没有 yield 了，函数结束
```

**调用它，里面的代码一行都不会执行**，只返回一个"生成器"对象：

```python
g = with_yield()          # 什么都没有打印！
print(type(g))            # <class 'generator'>
```

**要让代码跑起来，得推进它**：

```python
print(next(g))            # 打印"第一步"，然后输出 1
print(next(g))            # 打印"第二步"，然后输出 2
print(next(g))            # 打印"第三步"，然后报 StopIteration
```

### 3.3 用一张图记住

```
普通函数：  开始 ──→ 执行 ──→ return ──→ 结束（状态销毁）

yield 函数：开始 ──→ 执行 ──→ yield ▶ 暂停（状态保留）
                     ↑                    │
                     └──── next() ────────┘
```

> **`yield` = "我把东西交出去，然后在这里挂起，等我被再次唤醒就接着往下走。"**

### 3.4 这和"收尾"有什么关系

**`yield` 后面的代码，天然就是收尾的位置**：

```python
def get_conn():
    conn = db.get_conn()      # 准备
    try:
        yield conn            # ← 把连接交出去，然后暂停在这里
    finally:
        conn.close()          # ← 框架用完了，回来继续执行这里
```

框架的逻辑是：

1. 调你的依赖函数 → 拿到生成器
2. `next()` 推进到 `yield` → 拿到连接
3. **把连接交给接口函数用**
4. 接口函数返回后 → 再 `next()` 一次 → 执行 `yield` 后面的收尾

**`yield` 把"准备"和"收尾"写在同一个函数里，中间那段是别人在用。** 这就是它在这里的全部意义。

## 四、动手：`backend/deps.py`

新建 `backend/deps.py`：

```python
from collections.abc import Generator
from typing import Annotated

from fastapi import Depends

import db


def get_conn() -> Generator:
    """每个请求一个连接，请求结束后自动提交/回滚并关闭。"""
    with db.get_db() as conn:
        yield conn


ConnDep = Annotated[object, Depends(get_conn)]
```

**逐段看：**

| 代码 | 作用 |
|---|---|
| `from collections.abc import Generator` | 类型标注用；这些是第 6 课说的"标注"，不是运行时强制 |
| `with db.get_db() as conn:` | 又用上了第 8 课的上下文管理器 |
| `yield conn` | 把连接交出去，然后暂停 |
| `ConnDep = Annotated[object, Depends(get_conn)]` | **给"带依赖的类型"起个短名字** |

### 关于 `Annotated`

`Annotated[类型, 附加说明]` 的意思是：**"这是 X 类型，另外附带这条信息给框架看。"**

```python
conn: Annotated[object, Depends(get_conn)]
#     └─ 类型 ─┘  └─ 告诉 FastAPI：这个值从 get_conn 来 ─┘
```

**不起别名也完全可以**，两种写法等价：

```python
# 写法 A：直接写在参数上
def create_profile(req: ProfileRequest, conn: Annotated[object, Depends(get_conn)]):
    ...

# 写法 B：起个别名（推荐）
ConnDep = Annotated[object, Depends(get_conn)]

def create_profile(req: ProfileRequest, conn: ConnDep):
    ...
```

**用 B 的理由**：以后要改（比如换成连接池、加上用户身份校验），**只改 `deps.py` 一行**，20 个接口不用动。这正是第一节说的"改不动"问题的解法。

> 真实项目里，`deps.py` 里会逐渐攒出 `CurrentUser`、`DB`、`Pagination` 这些别名。**一个文件，管所有"接口需要的东西"。**

## 五、改接口

`routers/profile.py`：

```python
from fastapi import APIRouter, HTTPException

from deps import ConnDep
from schemas import ProfileRequest, ProfileResponse

router = APIRouter(prefix="/profile", tags=["学生画像"])


@router.post("", response_model=ProfileResponse)
def create_profile(req: ProfileRequest, conn: ConnDep):
    cur = conn.cursor()
    cur.execute(
        "insert into students(name, major, age, goal) values (?, ?, ?, ?)",
        (req.name, req.major, req.age, req.goal),
    )
    new_id = cur.lastrowid

    return ProfileResponse(
        id=new_id,
        name=req.name,
        major=req.major,
        age=req.age,
        goal=req.goal,
    )


@router.get("/{student_id}", response_model=ProfileResponse)
def get_profile(student_id: int, conn: ConnDep):
    cur = conn.cursor()
    cur.execute(
        "select id, name, major, age, goal from students where id = ?",
        (student_id,),
    )
    row = cur.fetchone()

    if row is None:
        raise HTTPException(status_code=404, detail="不存在这个学生")

    return ProfileResponse(
        id=row[0], name=row[1], major=row[2], age=row[3], goal=row[4]
    )
```

**`import db` 和 `with ...` 都不见了。** 接口里只剩下**真正要做的事**。

### 5.1 注意：`commit` 的时机变了

原来的写法：

```python
with db.get_db() as conn:
    cur.execute("insert ...")
# ← 这里就 commit 了，在 return 之前
return ProfileResponse(...)
```

现在的写法：

```python
def create_profile(req, conn: ConnDep):
    cur.execute("insert ...")
    return ProfileResponse(...)      # ← 函数先返回
    # 然后 FastAPI 才回来执行 get_conn 的收尾，才 commit
```

**commit 发生在函数返回之后。** 意味着：

- 如果 commit 本身失败（磁盘满、约束冲突），**错误发生在响应已经组织好之后**
- 这个差别在调 LLM 那种"慢且可能失败"的操作上要留意**（以后会碰到）**

> 现在不用处理，**但要知道"看起来一样的两段代码，执行顺序可能不同"**。

### 5.2 一个额外的收获：`raise HTTPException` 会自动回滚

你现在的 `get_profile` 在 `with` 里面 `raise` 了：

```python
    if row is None:
        raise HTTPException(status_code=404, detail="不存在这个学生")
```

**`HTTPException` 也是异常** → `__exit__` 收到 `exc_type != None` → **执行 `rollback()` 而不是 `commit()`**。

对只读查询无所谓，但对写入接口意义很大：

> **接口中途失败，不会留下写了一半的数据。**

这是第 8 课学的 `__exit__` 分支判断，在这里自动生效了——**你没写任何额外代码**。好的抽象就是这样：**正确的行为是免费附带的**。

## 六、一个关键机制：依赖缓存

**在同一个请求里，FastAPI 对同一个依赖只执行一次。**

意思是：

```python
def a(conn: ConnDep): ...

def b(conn: ConnDep): ...
```

如果一个接口同时需要 `a` 和 `b`（比如用 `dependencies=[...]` 或有嵌套依赖），**`get_conn` 只会被调用一次，两个函数拿到的是同一个连接**。

> **这就是我上一课说的"一个请求内共用同一个连接"。**
>
> 它同时也意味着一个约束：**`conn` 只能在这次请求内使用，别把它存到全局变量里。** 请求结束后连接就关了，再拿它用会报错。

## 七、几个会遇到的坑

### 7.1 依赖函数里写了 `return` 而不是 `yield`

```python
def get_conn():
    conn = db.get_conn()
    return conn            # ❌ 能跑，但没人关闭它
```

**能跑，但连接永远不关。** 而且**不报错**——又是第 7 课那种"看起来对了"。

> 这是本节课最容易犯的错：**语法上没错，语义上错了。** 只能靠记住"要收尾就必须 `yield`"。

### 7.2 在 `yield` 后面写 `except` 吞掉异常

```python
def get_conn():
    with db.get_db() as conn:
        try:
            yield conn
        except Exception:
            pass                    # ❌ 第 8 课说过了
```

**别做。** 异常被吞掉，接口看起来正常返回，但其实是出错了。

### 7.3 以为 `Annotated[object, ...]` 里的 `object` 有校验作用

**没有。** 那是给人和 IDE 看的标注，FastAPI 不会检查 `conn` 到底是不是那个类型。

想真正约束类型，用具体的类：

```python
import sqlite3

ConnDep = Annotated[sqlite3.Connection, Depends(get_conn)]
```

> **类型标注在 Python 里默认是"给人看的"，不是"运行时强制的"。** 第 6 课讲过——`name: str` 在普通函数里写错了也没人管，**只有在 Pydantic 模型和 FastAPI 参数里才被当作规则执行**。

### 7.4 `deps.py` 反过来 `import` 了 routers

`deps.py` 只应该依赖 `db.py` 这种底层。**别让它引用上层的 router**，否则就是第 9 课说的循环导入。

```
main → routers → deps → db
```

## 十一、备忘
